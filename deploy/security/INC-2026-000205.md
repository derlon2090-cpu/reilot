## Origin deployment

After copying this checkout to the Linux origin, run:

```bash
sudo install -m 0750 deploy/security/block-current-incident-batch /usr/local/sbin/block-current-incident-batch
sudo /usr/local/sbin/block-current-incident-batch
sudo systemctl is-active renvix-honeypot-sentry.service
sudo ipset list honeypot_blacklist
```

The batch command inserts the existing shared set's DROP rule at INPUT index 1,
also protects Docker's `DOCKER-USER` chain when present, saves the ipset and
firewall rules, then verifies all eight entries. It does not touch SSH remotely
from this workspace.

## Edge and Nginx deployment

Install the updated `cloudflare-latest-incidents-rule.json` through the existing
Cloudflare WAF installer/control plane. Merge the updated `deploy/nginx.conf`
and `deploy/security/probe-log.conf` into the deployed Nginx config, then run:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

The honeypot remains telemetry-first. Kernel bans are restricted to the
validated reserved probe events consumed by `renvix-honeypot-sentry`; this
change does not trust client-supplied `X-Forwarded-For`, ban every first hit,
or apply a blanket ASN deny.
