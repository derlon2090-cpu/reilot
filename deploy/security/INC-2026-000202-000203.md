# INC-2026-000202 / INC-2026-000203

Repository preparation only. No production host or Cloudflare account was
changed from this workspace.

## Observed indicators

- Sources: `34.152.30.165`, `34.52.133.111`
- Reported ASN: `AS396982` (Google Cloud)
- Routes: `/pinfo.php`, `/api/phpinfo.php`, `/.git/config`, `/credentials`
- Target: isolated `admin-honeypot`

## Prepared containment

- Both source addresses are seeded into `honeypot_blacklist` for seven days.
- Nginx returns `444` for the new runtime and credential routes, and already
  covers Git metadata. Requests are excluded from the general access log.
- A minimal fixed-format local line drives a first-hit kernel sentry without
  retaining paths, query strings, headers or bodies.
- Cloudflare blocks the two confirmed sources globally and blocks the sensitive
  routes on production hosts. Other sources can still reach the isolated
  honeypot so it can retain bounded telemetry.
- `AS396982` is already in the managed-challenge rule for non-exempt routes.
  It is not globally blocked because that would affect legitimate GCP users.

## Deployment

Run from the repository checkout on the Linux origin:

```bash
sudo install -m 0750 deploy/security/install-honeypot-blacklist /usr/local/sbin/install-honeypot-blacklist
sudo /usr/local/sbin/install-honeypot-blacklist

sudo install -m 0750 deploy/security/install-honeypot-sentry /usr/local/sbin/install-honeypot-sentry
sudo /usr/local/sbin/install-honeypot-sentry

sudo install -m 0644 deploy/security/probe-log.conf /etc/nginx/conf.d/00-probe-log.conf
# Merge deploy/nginx.conf into the live virtual host, preserving TLS settings.
sudo nginx -t && sudo systemctl reload nginx

sudo /usr/local/sbin/install-probe-waf \
  deploy/security/cloudflare-probe-expression.txt \
  deploy/security/cloudflare-cloud-asn-expression.txt \
  deploy/security/cloudflare-protocol-abuse-expression.txt \
  deploy/security/cloudflare-latest-incidents-expression.txt
```

The sentry and the enabled Fail2ban jail are alternatives for the same local
first-hit action; do not enable both unless duplicate idempotent actions and
logs are acceptable. For Cloudflare-proxied requests, the origin kernel sees a
Cloudflare proxy address, not the visitor. Keep Cloudflare-only origin ingress
and use the edge rule/action for visitor containment.

## Verification

```bash
sudo ipset test honeypot_blacklist 34.152.30.165
sudo ipset test honeypot_blacklist 34.52.133.111
sudo systemctl is-active renvix-honeypot-sentry
sudo nginx -t
sudo tail -n 20 /var/log/renvix/honeypot-sentry.log
```

Use a controlled, non-administrative source to request one reserved path.
Expect the triggering HTTP transaction to close without a response (`444`),
then expect subsequent direct-origin connections to time out at the kernel.
Latency depends on Nginx log delivery and process scheduling; it is designed
for immediate first-hit handling but is not truthfully guaranteed to be
sub-millisecond.
