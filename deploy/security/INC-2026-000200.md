# INC-2026-000200 — Legacy WordPress manifest probe

Status: repository controls prepared and verified. Production host execution
requires an authenticated Linux administration session; source control alone
cannot mutate the kernel ipset or reload Nginx.

## Telemetry

- Source: `185.19.40.179`
- Target: `admin-honeypot`
- Vector: `//test/wp-includes/wlwmanifest.xml`
- Classification: routine framework probe, recorded as silent telemetry

## Production application

Run from the repository checkout on the protected Linux host:

```bash
sudo install -m 0750 deploy/security/install-honeypot-blacklist /usr/local/sbin/install-honeypot-blacklist
sudo /usr/local/sbin/install-honeypot-blacklist
sudo ipset test honeypot_blacklist 185.19.40.179

sudo install -m 0644 deploy/security/probe-log.conf /etc/nginx/conf.d/00-probe-log.conf
# Merge deploy/nginx.conf into the active HTTPS server configuration.
sudo nginx -t
sudo systemctl reload nginx
```

The installer atomically upgrades an older `honeypot_blacklist` to timeout
support without replacing its iptables reference. Following the repeat event
recorded as INC-2026-000204, `185.19.40.179` is now a confirmed repeat source
and is stored persistently with `timeout 0`.

## Verification

```bash
sudo ipset list honeypot_blacklist
sudo iptables -w -C INPUT -m set --match-set honeypot_blacklist src -j DROP
sudo nginx -T | grep -F 'location ~* ^/+.*(wp-includes|wlwmanifest\.xml)'
```

The Nginx route returns an empty `444` and disables both access and not-found
logging. On the isolated Cloudflare admin honeypot, the same path is classified
as `framework_probe`, sent only to the signed Renvix ingestion endpoint, stored
with `realtimeNotificationsSuppressed=true`, and excluded from alert-webhook
delivery unless a separate non-silent security signal later joins the incident.
