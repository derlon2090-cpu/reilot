# INC-2026-000204 — Repeat WordPress manifest probe

Status: repository controls prepared. Production execution still requires an
authenticated Linux host session and Cloudflare credentials.

## Telemetry

- Source: `185.19.40.179`
- Target: isolated `admin-honeypot`
- Vector: `//site/wp-includes/wlwmanifest.xml`
- Classification: routine framework probe with real-time notifications suppressed

The Nginx and Worker path classifiers already accept consecutive leading
slashes. This recurrence therefore does not prove a regex bypass. It indicates
that the production controls may not have been deployed/enabled, or that the
event reached the Cloudflare Worker where the origin kernel never sees the
visitor address.

## Correct immediate triage

An individual member of an ipset does not appear in `iptables -L`. Check both
the set membership and the single firewall rule that references the set:

```bash
sudo ipset test honeypot_blacklist 185.19.40.179
sudo iptables -w -C INPUT -m set --match-set honeypot_blacklist src -j DROP
sudo systemctl status renvix-honeypot-sentry.service
sudo journalctl -u renvix-honeypot-sentry.service -n 100 --no-pager
```

Install and run the idempotent triage helper to inspect, block permanently,
persist, and print the service journal in one operation:

```bash
sudo install -m 0750 deploy/security/triage-honeypot-ban /usr/local/sbin/triage-honeypot-ban
sudo /usr/local/sbin/triage-honeypot-ban 185.19.40.179
```

The equivalent compact command is:

```bash
sudo sh -c 'ipset create honeypot_blacklist hash:ip family inet timeout 0 -exist && ipset add honeypot_blacklist 185.19.40.179 timeout 0 -exist && (iptables -w -C INPUT -m set --match-set honeypot_blacklist src -j DROP 2>/dev/null || iptables -w -I INPUT 1 -m set --match-set honeypot_blacklist src -j DROP) && ipset save > /etc/ipset.conf && netfilter-persistent save'; sudo systemctl --no-pager --full status renvix-honeypot-sentry.service; sudo journalctl --no-pager -u renvix-honeypot-sentry.service -n 100
```

## Edge and alert policy

The confirmed repeat source is included in the terminating Cloudflare incident
rule. This matters for `admin-honeypot`: a host `INPUT` rule cannot block the
visitor IP on a proxied Worker request. Deploy the WAF update and verify the
rule by read-back. `EDGE_AUTO_BLOCK` remains opt-in and must be explicitly
enabled only after configuring the account ID, scoped token, and trusted test
IP exemptions.

Do not mute every `admin-honeypot` event permanently. Routine framework probes,
including both single- and double-slash `wlwmanifest.xml` paths, already set
`realtimeNotificationsSuppressed=true`; HIGH/CRITICAL correlated incidents must
remain capable of paging operators.
